# Live demo on Render (no tunnel, laptop can be off)

This project ships a **Render Blueprint** (`render.yaml`): one Docker service (API + in-container platform mocks) + managed PostgreSQL.

## Why Render

- **HTTPS URL** for the IncuBrix submission form  
- **Docker** matches your assessment (`Dockerfile` + compose locally)  
- **No tunnel** — runs 24/7 on Render’s servers  
- **Starter plan** (~$7/mo web + small DB) keeps the demo awake during review (free tier sleeps after ~15 min — cold starts are slow for reviewers)

## Steps

### 1. Push code to GitHub

Create a private repo and push `Outpost` (if you have not already).

### 2. Create Render account

https://render.com → sign up → connect GitHub.

### 3. Deploy from Blueprint

1. **New +** → **Blueprint**  
2. Select your `Outpost` repository  
3. Render reads `render.yaml` and creates **outpost-api** + **outpost-db**  
4. Wait for the first deploy (build can take 5–10 minutes)

### 4. Set public URL env var

After deploy, copy your service URL, e.g. `https://outpost-api-xxxx.onrender.com`

In the **outpost-api** service → **Environment**:

| Key | Value |
|-----|--------|
| `PUBLIC_BASE_URL` | `https://outpost-api-xxxx.onrender.com` (your real URL) |

Save → redeploy.

### 5. Get demo token for reviewers

In **Environment**, open **`DEMO_API_KEY`** (auto-generated by Blueprint).

Share with IncuBrix:

- **Live demo URL:** `https://your-service.onrender.com/docs`  
- **Access:** header `X-Demo-Token: <DEMO_API_KEY>` on API calls (not required for `/docs`, `/health`, `/demo-info`)

Public check:

```bash
curl https://YOUR_URL/api/v1/health
curl https://YOUR_URL/api/v1/demo-info
```

Authenticated example:

```bash
curl -H "X-Demo-Token: YOUR_KEY" https://YOUR_URL/api/v1/destinations
```

### 6. Verify certification on the live URL

```powershell
python scripts/run_certification.py --base-url https://YOUR_URL.onrender.com
```

(Add `-H` support in script if needed — or set `DEMO_API_KEY` in script; for now use env in requests from browser/docs: use Authorize in Swagger if we add it — docs are public, Try it out needs header manually)

In Swagger **Try it out**, add header `X-Demo-Token` per request, or use a browser extension.

### 7. Submission form text (template)

- **Live demo URL:** `https://….onrender.com/docs`  
- **Token:** `X-Demo-Token` (value from Render env)  
- **Cold start:** ~30–60s on free tier if idle; Starter stays warm  
- **Rate limit:** 120 requests/minute/IP  

## Local Docker vs Render

| | Local `docker compose` | Render |
|--|------------------------|--------|
| Postgres | Container | Managed DB |
| Mocks | Separate container | Same container as API (`start_production.sh`) |
| MinIO | Optional profile | Off (`S3_ENABLED=false`) |

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Build fails | Check Render logs; ensure `Dockerfile` builds locally: `docker build .` |
| DB connection error | `DATABASE_URL` must be set from Render Postgres (Blueprint does this) |
| 401 on API | Set `X-Demo-Token` or unset `DEMO_API_KEY` only on local dev |
| Certification fails | Mocks run inside container; check logs for `127.0.0.1:8080` |

## Alternative (Railway)

Same `Dockerfile` + `start_production.sh`: create a Railway project → deploy from GitHub → add PostgreSQL plugin → set the same env vars as in `render.yaml`.
