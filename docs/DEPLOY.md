# Live demo — $0 (Render Free + Neon Postgres)

Host the API on **Render’s free web tier** and the database on **Neon’s free tier**. No tunnel; your laptop can be off.

| Component | Provider | Cost |
|-----------|----------|------|
| Docker API + in-container mocks | Render **Free** | $0 |
| PostgreSQL | [Neon](https://neon.tech) **Free** | $0 |

**Trade-off:** Render free services **sleep** after ~15 minutes without traffic. The first request after sleep may take **30–60 seconds** (cold start). Tell reviewers in your submission form.

**Paid upgrade (optional):** Render **Starter** (~$7/mo) stays warm if cold starts are a problem during review week only.

## Prerequisites

- Code on GitHub: https://github.com/kaviya-ns/Outpost  
- Accounts: [Render](https://render.com), [Neon](https://neon.tech) (both free signup)

---

## Part A — Neon database (5 minutes)

1. Log in to **Neon** → **New Project** (e.g. `outpost-demo`).
2. Open **Dashboard** → **Connection details**.
3. Copy the **connection string** (PostgreSQL).  
   - Use the pooled URL if offered (`-pooler` host) — either works; the app rewrites to `postgresql+asyncpg://` automatically.
4. Keep this secret; you will paste it into Render as `DATABASE_URL`.

Example shape (not real credentials):

```text
postgresql://user:password@ep-xxxx.region.aws.neon.tech/neondb?sslmode=require
```

Keep `?sslmode=require` on the Neon URL — the app strips it and enables TLS for asyncpg automatically.

## Part B — Render web service

### Option 1 — Blueprint (recommended)

1. Render → **New +** → **Blueprint**.
2. Connect repo **kaviya-ns/Outpost** → apply `render.yaml`.
3. Render creates **outpost-api** on the **Free** plan (no Render database).
4. Before or right after first deploy, open **outpost-api** → **Environment** and set:

| Key | Value |
|-----|--------|
| `DATABASE_URL` | Neon connection string from Part A |
| `PUBLIC_BASE_URL` | `https://<your-service-name>.onrender.com` (exact URL from Render **Settings**) |

5. **`DEMO_API_KEY`** — auto-generated by the blueprint; copy it for reviewers.
6. **Save** → **Manual Deploy** (or wait for redeploy).

### Option 2 — Manual web service

1. **New +** → **Web Service** → connect GitHub **Outpost**.
2. **Language:** Docker  
3. **Plan:** Free  
4. **Health check path:** `/api/v1/health`  
5. Add the same environment variables as in the table above (+ `S3_ENABLED=false`, `SIMULATION_MODE=true` from `render.yaml` if you want parity).
6. Create service → deploy.

## Part C — Verify

Public (no token):

```bash
curl https://YOUR-SERVICE.onrender.com/api/v1/health
curl https://YOUR-SERVICE.onrender.com/api/v1/demo-info
```

With demo token:

```bash
curl -H "X-Demo-Token: YOUR_DEMO_API_KEY" https://YOUR-SERVICE.onrender.com/api/v1/destinations
```

Browser:

- Docs: `https://YOUR-SERVICE.onrender.com/docs`  
- In Swagger **Try it out**, add header `X-Demo-Token` for protected endpoints.

Certification from your PC:

```powershell
$env:DEMO_API_KEY="your-key-from-render"
python scripts/run_certification.py --base-url https://YOUR-SERVICE.onrender.com
```

## What runs in the cloud

Single Docker container (`scripts/start_production.sh`):

- Platform **mocks** on `127.0.0.1:8080` (Discourse, Dev.to, Lemmy, Ghost, webhook)  
- **FastAPI** on Render’s `$PORT`  
- **No MinIO** (`S3_ENABLED=false`)  
- **Postgres** on Neon via `DATABASE_URL`

Local `docker compose` is unchanged for development (separate mocks container + optional MinIO profile).

## Troubleshooting

| Issue | Fix |
|-------|-----|
| Deploy fails immediately | Set `DATABASE_URL` to Neon URL; redeploy |
| `SSL` / connection errors | Neon URL must include `?sslmode=require` if Neon shows it |
| Build fails | Run `docker build .` locally; check Render build logs |
| 401 on API | Send `X-Demo-Token`; `/health`, `/docs`, `/demo-info` stay public |
| Certification fails on live | Check Render **Logs** for mock/API errors; wake service with `/health` first |
| Very slow first request | Normal on **Free** — hit `/health` once before demo |

## Optional paid path

Edit `render.yaml` → `plan: starter` and add a Render Postgres database block only if you want everything on Render and no cold sleep. For $0, keep **Free + Neon** as above.

## Other hosts

Same `Dockerfile` and env vars work on **Fly.io**, **Railway**, or a small **Oracle Cloud Always Free** VM with `docker compose`. Neon `DATABASE_URL` stays the same.
